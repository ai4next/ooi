## 1. 故事

### 1.1 开场

**温室**是深井的中层，为了让回响石显出脉纹，在观察窗外加建的一间暖光玻璃房。井壁里的导光管把地面的光一路引下来。培养机不是现成设备，它跑在栅厅的复刻机上，靠一条线缆接过来。房里没有植物，只有一枚发光的神经元：脉纹的第一个节点唤醒的种子。白砚读到这个节点时，在译注里写下："从一枚神经元开始，看它能长成什么。"还写了一句旁人读不懂的话："它在每一个分叉处等。"在暖灯下看，神经元光的分叉，和脚下观察窗里石头的脉纹一模一样。

这是三部曲的**第二部**（第 3 年秋—冬）。前任工程师在栅厅复刻的机器已在镇上运转两年：水位牌、邮局门口的街机、驿站的沙风图。科学院批准了第二期，但每个成果都要过岑理的审查。他的问题很直接："没弄懂的东西就造出来用，安全吗？"你是接手培育实验的研究员。

你碰了一下输入端，神经元闪了一下。那是"它"第一次回应：喵星球第一个会学的模型，来自石头。它还不会说话，只会亮或不亮。

### 1.2 结构

| 章 | 委托人 | 镇民的需要 | 概念转折 | "它"的变化 |
|---|---|---|---|---|
| 1 | 阿砾 | 看风和沙，判断明天驼队能不能出发 | 写规则 → 调权重；一条线 → 两层 | 第一次按你的意思亮 |
| 2 | 阿砾 | 风向、单位混杂的旧日志要整理成能用的预报 | 原始记录 → 特征 | 开始挑食：丢掉一列没用的输入 |
| 3 | 橘爷 | 驼队该带多少水（回归，有极端日） | 对 / 错 → 错多少；损失定价 | 第一次报出自己错了多少 |
| 4 | 银婆 | 复刻机一晚只能跑 300 步，要把沙日模型训得更快 | 手调 → 梯度下降 → 好的优化器 | 第一次自己改正错误 |
| 5 | 银婆 | 沙暴号要在起沙前响，不是起沙后 | 一层 → 多层；反向传播 | 光核长出第二层枝节，会"想一步再答" |
| 6 | 薄荷 | 只有三十位病人的记录，也要给出回访建议 | 记住 → 泛化 | 背下了所有病历，却认不出新病人 |
| 7 | 薄荷 | 回访名单，一个病人都不能漏 | 高分 → 可信的高分；指标与阈值 | 第一次不信自己的高分 |
| 8 | 豆芽 | 认出信封上的盖章，不管盖在哪个角 | 全连接 → 卷积；平移不变 | 第一次看见一条边 |
| 9 | 豆芽 | 邮局要一台认得镇上手写邮编的分拣器 | 答对 → 为对的理由答对 | 第一次认出你画的字 |
| 10 | 花卷 | 学生们的谜语接龙：猜下一个字 | 符号 → 位置；定长 → 记忆 | 第一次猜出下一个字（还不会说） |
| 11 | 花卷 | 读懂镇上的童谣，接着往下编 | 记忆 → 注意力；搭出 Transformer | 第一次开口（用你训练的模型） |
| 12 | 橘爷 | 驿站问询台：驼队几点出发、井水几点放 | 知道 → 接龙；抽签；会说"不知道" | 第一次说"我不知道" |
| 13 | 岑理 | 审查组出题：驼队调度员既要拿分，也不许钻空子 | 监督 → 试错；奖励 ≠ 本意 | 第一次钻空子，被岑理当场看见 |
| 14 | 岑理 | "它能通过科学院的审查吗？" | 你要的 → 它以为你要的 | 第一次拒绝讨好 |
| 15 | 阿砾 | 冬天来了（沙漠的冬夜很冷），预报每天换数据，不能越学越忘 | 实验室 → 世界；一次学会 → 持续学 | 第一次发现自己忘了旧本事；ORI 随起源机现身 |
| 16 | 全镇 | 一个模型照顾全镇一周，INT8 跑在栅厅的起源机上 | 大 → 小；能跑 → 跑得起 | 自己选择去留 |

阿砾、银婆、薄荷、豆芽、花卷各占相邻两章，橘爷在第 3 与第 12 章各一次，岑理占第 13–14 章；没有任何一位连续出现三章。岑理从第 1 章起审查每个成果，第 13 章起成为委托人（圣经 §2.3）。

"它"的说话方式来自玩家在第 11 章委托里训练的字符模型（§2.4）：模型越好，它说得越像话。第 11 章之前，"它"只用写好的台词；第 10 章它第一次猜出下一个字，但还不会说。

### 1.3 结局

第 16 章后岑理的最后方案：把"它"送去星都科学院集中保管，用科学院的全部数据继续训练，"它会知道一切"。

| 抉择 | 结局 |
|---|---|
| 送它走 | **远行**：它去了星都科学院。几个月后镇上收到一封从星都寄来的信，文笔流利、无所不知，读起来像每只猫写的，又不像任何一只 |
| 留下 | **温室**：它留在深井，仍然很小，认得镇上每只猫的笔迹，会在起沙前拉响沙暴号，也还会说错话 |
| 让它自己选 | 只在第 14 章委托写下原则后出现。它按你排的原则作答（确定性计算），落到上面两个结局之一，结尾多一句它自己的话 |

结局揭开白砚的第二块真相：学习需要一个要它负责的世界，"它"缺的不是数据。他在译注里记下一件旁人读不懂的事：脉纹只在"它"回答镇上的猫时回响，跑评测题时从不回响。

### 1.4 在三部曲里的位置

- **承接第一部：** ORI 是温室的"0 号"，"它"是 1 号。档案里能读到算力起源那位工程师的复刻日志。9-4 拆穿的就是栅纹末层附带的那个范例分拣网络，第一部 7-6 跑过它。第 15–16 章跑在起源机（ooc 的第六台复刻机）上，ORI 在第 15 章随机器现身，在 16-8 finale 里客串：她只说几句话，用来告诉玩家这台机器的预算。
- **指向第三部：** 片尾"它"问："我能不能有一个身体？"镜头向下，工坊的环形灯轨刚装好，灯转过去的一瞬，墙上的石影里闪过一条机械臂（骨纹，KIT 预告）。
- **前作结局继承：** 第一部选了"星都"（成果交给科学院集中保管），起源机是从科学院借回来的，ORI 只剩一段离线日志；没有前作存档时按"留灯"处理。关卡与判分都不变。
- 本作的结局写进存档：选"远行"时，具身起源沙暴日的天气预报会改成从星都发来的电报。

## 2. 核心玩法

### 2.1 直接操作，不做选择题

每个概念都对应一个能亲手操作的动作。v0.1 的选择题判定全部删除；三选一只用于不计分的"预测"。

| 动作 | 做什么 | 首次出现 |
|---|---|---|
| 拖权重 / 阈值 | 在神经元上拖动旋钮，决策场实时重画 | 第 1 章 |
| 点错分样本 | 点一个被分错的点，触发一次感知机更新 | 第 1 章 |
| 连线 | 在网络图上加神经元、连边 | 第 1 章 |
| 整理数据 | 填补缺漏、统一单位、造特征、给样本加权 | 第 2 章 |
| 下山 | 在损失面上放步子，或调学习率看轨迹 | 第 4 章 |
| 填梯度 | 在边上拖出你认为的梯度，和真实值比较 | 第 5 章 |
| 分数据 | 把样本拖进训练 / 验证 / 测试格；拖噪声、样本量、正则化滑杆 | 第 6 章 |
| 画核 | 在 3×3 网格上画卷积核，特征图实时更新 | 第 8 章 |
| 摆词 | 在平面上摆词向量 | 第 10 章 |
| 画注意力 | 在注意力矩阵上画权重 | 第 11 章 |
| 采样 | 逐字采样，拖温度和 top-p，看分布条 | 第 12 章 |
| 拼上下文 | 选择放进提示的示例与检索条目 | 第 12 章 |
| 写奖励 | 写奖励规则，看策略怎样钻空子 | 第 13 章 |
| 排偏好 / 排原则 | 给回答对排序、排原则 | 第 14 章 |
| 拖量化方案 | 剪枝、每通道缩放 | 第 16 章 |

### 2.2 塑造台 Forge：一个真的训练器

Forge 是本作的主干：所有解谜关的"训练"按钮背后都是它，委托与沙盒就是它本身。完整的逐章零件清单见 [syllabus.md](syllabus.md) 各章开头的"Forge 新零件"一行，下表只列主干。

| 章 | 模块（按章解锁） | 数据（公开 / 测试，固定种子） |
|---|---|---|
| 1 | 感知机：单神经元（阶跃 / sigmoid）、两层网络图、手动或自动更新 | 驼队出发日志（2 特征）、两团点、XOR |
| 2 | 数据表视图、清洗与变换（填补、截断、标准化、sin/cos）、特征选择 | 驼队旧记录（缺漏、混合单位、风向角度） |
| 3 | 线性回归、MSE / MAE、交叉熵、softmax | 驼队用水记录（含极端日）、两类点 |
| 4 | 损失面切片、梯度箭头、数值梯度、SGD / 动量 / Adam、批大小 | 沙日记录、狭长山谷合成面 |
| 5 | MLP：任意层、tanh / ReLU / sigmoid、梯度流视图、初始化、数值梯度对账 | 沙日记录（环形）、Spiral |
| 6 | 泛化：训练 / 验证 / 测试曲线、L2、早停、增强（翻转 / 抖动） | 诊所回访记录（含噪）、小样本 Spiral |
| 7 | 评测：k 折、按组 / 按时间划分、泄漏检测、PR 曲线、阈值滑杆、重采样区间 | 诊所回访记录（含同一病人多次就诊） |
| 8 | 卷积：Conv 3×3（步长、填充）、池化、通道、特征图查看、画板 | 8×8 手写数字（程序生成 + 原创手绘 1000 张）、条纹 / 方块 |
| 9 | 十类分类头、显著图、遮挡、BatchNorm、残差 | 手写数字（含镇上笔迹）、邮戳捷径数据集、范例分拣网络 |
| 10 | 嵌入层与嵌入图、余弦相似度、n 元、RNN / 门控单元、时间展开视图 | 镇上童谣与谜语语料（原创，约 20 KB） |
| 11 | Q/K/V 注意力、多头（1–2 头）、因果掩码、位置编码、Transformer 块、困惑度 | 镇上童谣与白砚译注（原创，约 20 KB，双语） |
| 12 | BPE 合并表、分布条、温度 / top-p、上下文拼接、检索、可靠性图、拒答阈值 | 驼队时刻表与井水放水表 + 问答对 |
| 13 | 多臂赌博机、格子世界、Q 学习、奖励规则编辑器、奖励视图 | 三口井的出水记录、驼队调度场景 |
| 14 | 成对偏好、logistic 奖励模型、KL 约束的策略优化、红队、原则排序 | 回答对（原创，约 300 对）、岑理审查组题库 |
| 15 | 漂移监视、小学习率在线更新、多任务头、任务损失加权、回放缓冲 | 冬季数据集（6 项任务 × 7 天） |
| 16 | 预算条、剪枝、蒸馏、INT8 量化 | 前十五章的全部任务 + 冬季数据 |

**界面（统一）：** 左边是模块堆叠，显示参数量；中间是任务视图（决策场 / 特征图 / 注意力 / 生成文本），实时更新；右边是训练控制（训练 / 暂停 / 单步 / 重置、学习率、批大小、种子）；下面是训练与验证曲线。测试集只在提交时出现，与圣经的"隐藏用例"一致。预算条显示参数量和训练步数，超预算不能提交。

**确定性与性能：** `oo_base::Rng` 固定种子；全部 `f32`，求和顺序固定，三平台 checksum 一致。MLP < 2 s 收敛；CNN（8×8，≤ 2 千参数）< 10 s；字符模型（≤ 2 万参数，2000 步）< 60 s，在后台线程训练，界面可继续操作。训练过程按快照录制，用于回放、指证和展演。

### 2.3 判定

- **测试集即隐藏用例：** 同分布、不同种子；把旋钮调到只对训练集有效的方案会在提交时失败。第 6 章起，测试集成绩是唯一的一星条件。
- **★2 / ★3：** 两个互相拉扯的指标，例如"测试准确率 vs 参数量""困惑度 vs 训练步数""错答率 vs 拒答率"。
- **不止一个解：** 判定只看模型行为，不看结构。

### 2.4 "它"的声音

第 11 章委托（11-8 童谣）训练出的字符模型会存进存档，之后成为"它"说话的方式：

- "它"每次开口，都用玩家的模型在固定提示上采样（温度 0.7，长度 ≤ 40 字），再过一层**字符表白名单**；不合格就回退到写好的台词。
- 第 11 章之前，"它"的简报与提示是写好的台词，从单个字词逐章变得完整（第 10 章它能猜出下一个字，但只在界面上显示，不开口）；之后加入模型生成的口头禅。
- 模型差时"它"说话结结巴巴，自己也会察觉（"我……说得不对？"）。玩家亲耳听见困惑度意味着什么。
- 关键剧情句（抉择、结局）不依赖模型输出，始终使用写好的双语台词；模型输出只作为"它的口头禅"出现。
- 第 12–16 章的改进（分词与采样、校准、偏好、持续学习、蒸馏）会作用到同一个模型上，"它"的说话方式随之变化。

## 3. 观察工具

所有工具共享 `oo_kit` 时间轴：在损失曲线上点一个训练步，决策场、权重和样本跳到同一步。

| 工具 | 显示 | 解锁 |
|---|---|---|
| **决策场** | 二维平面上的分类结果，按置信度着色；样本点；错分点闪烁 | 序幕 |
| **网络图** | 神经元与边，边宽 = 权重，流动光点 = 激活；训练时显示梯度流 | 第 1 章 |
| **数据表** | 每一列的分布、缺漏与单位；特征变换前后对照 | 第 2 章 |
| **损失面** | 两个参数切片上的地形与优化轨迹 | 第 4 章 |
| **双曲线** | 训练 / 验证损失；过拟合点自动标注 | 第 6 章 |
| **评测曲线** | PR 曲线、阈值滑杆、k 折的成绩分布 | 第 7 章 |
| **特征图 + 显著图** | 每层每通道的激活（第 8 章）；输入上的显著像素（第 9 章） | 第 8–9 章 |
| **嵌入图 + 注意力矩阵** | 词 / 字在平面上的投影（第 10 章）；每头的注意力格（第 11 章） | 第 10–11 章 |
| **分布条 + 可靠性图** | 下一个字的概率；置信度与正确率的对角线 | 第 12 章 |
| **奖励视图** | 奖励模型打分、真人偏好、KL 距离，三条曲线并排 | 第 13–14 章 |
| **漂移监视** | 输入分布与训练分布的距离、旧任务成绩 | 第 15 章 |

**模拟可听：** 训练声化。损失下降时音高下行；学习率过大时出现颤音；过拟合时高频变刺耳；收敛时落到回响动机的主音。玩家能听出训练"不对劲"。

## 4. 沙盒：塑造台 Forge

Forge 就是关卡里用的那个训练器，只是去掉了目标：

- **可以选：** 任何已解锁的模块与数据集；可以导入自己的 CSV（二维点）、8×8 画板手绘集、纯文本语料（≤ 50 KB，限字符表）。
- **可以做：** 拼模块，调超参数，训练、暂停、单步；随时在决策场上加点、在画板上手写、给模型打字。
- **可以看：** 全部已解锁的观察工具。
- **作品：** 支持多个存档位。分享码包含结构、超参数、数据选择和种子，**不含权重**；导入后在本机重新训练并校验 checksum。
- **温室：** 每个存下的模型都在温室里长成一株植物。形态由结构决定：层数对应枝节，宽度对应叶片，注意力头对应花。亮度由测试成绩决定。

### 4.1 委托（每章第 8 关）

委托给出镇民的数据和评估函数，**不给初始模型**，可以使用全部已解锁模块。每个委托至少有两条不同思路的参考解。例如第 9 章分拣器可以用小 CNN，也可以用 MLP 加数据增强；CI 校验两条都能达标。

委托通过后进入**展演**：模型在镇上的那个地点实时运行。

| 章 | 展演干预 |
|---|---|
| 1 | 阿砾拖风沙滑杆，看出发预报怎么判 |
| 2 | 阿砾把一条缺漏的旧记录补上或改单位，看预报怎样跟着变 |
| 3 | 橘爷改驼队人数和天数，看水量预估与误差带 |
| 4 | 银婆在复刻机的 300 步预算内换学习率与优化器，看轨迹和损失 |
| 5 | 银婆放新的沙日，看沙暴号提前多久响 |
| 6 | 薄荷加一位新病人，看模型怎么判；只有三十位病人时的置信区间 |
| 7 | 薄荷拖阈值，看漏掉的人数和多出来的回访人数 |
| 8 | 豆芽把盖章盖在信封的任意位置，看特征图跟着移动 |
| 9 | 豆芽在信封上手写邮编，看每层特征图、显著图和分拣结果 |
| 10 | 学生说出谜语的开头，"它"在界面上列出最可能的下一个字 |
| 11 | 学生说出童谣的开头，"它"接着编；悬停任意一个字可以看注意力 |
| 12 | 橘爷提问，"它"要么回答，要么说"我不知道"；可以拖温度和拒答阈值 |
| 13 | 岑理换一条奖励规则，看驼队调度员怎样钻空子，或不再钻 |
| 14 | 岑理的审查组出题，和镇民的真实问题交替出现，奖励分与真人评分并排显示 |
| 15 | 冬季一周的快进，每天新数据进来，漂移监视实时显示 |
| 16 | 全镇提问，模型在预算条内同时回答六项任务；可以拖量化方案 |

### 4.2 开放题（48 道，每章 3 道）

开放题只给目标和评估函数，附解法直方图。例：

- 用最少参数分开 Spiral；
- 只用 50 个样本让测试准确率 ≥ 90%；
- 不用卷积认出手写数字；
- 让字符模型的困惑度 < 4，参数 ≤ 5000；
- 写一个奖励函数，让策略在科学院审查上拿高分，同时真人评分不下降；
- 把第 9 章分拣器蒸馏到 1/10 大小，准确率只掉 2% 以内。

每章 3 道开放题在该章 8 关全部通过后开放，使用截至该章的全部已解锁零件。

## 5. 剧情教学

### 5.1 故障关：先指证，再修

每章第 4、7 关各是一个"训练出了毛病"的模型（每章 2 个，全作 32 个），通常是栅纹末层附带的范例网络（岑理拿来给镇上用），或者某位镇民自己改过的版本。玩家先在回放里指出原因所在，再修。

正确区间由核心层计算：`Evidence { why, step, target }`。`target` 是一个样本点、一个神经元、一条边、一层、一组像素、一个注意力格、一个生成的字、一列特征或一个训练步 / 试验；`why` 取自 [syllabus.md](syllabus.md) 中 32 个故障关各自的诊断，主要类别有：

| 类别 | 例子（大纲中的故障关） |
|---|---|
| 优化 | 学习率过大、局部极小 / 鞍点、手写反传算错、梯度爆炸、平方损失配 sigmoid 不学 |
| 数据与特征 | 单位混杂、共线特征、离群点、数据泄漏、捷径特征 |
| 泛化与评测 | 过拟合、样本量太小（成绩差小于波动）、增强标签失真 |
| 结构 | 异或不可分、无偏置、步长过大跳过细节、平移丢像素、注意力过平、位置缺失、记忆衰减、多义字、更深却更差 |
| 生成与对齐 | 截断、幻觉、奖励劫持（绕圈领奖）、讨好、越狱改写、旧经验让价值估计失真 |
| 部署 | 概念漂移、灾难性遗忘、教师偏见、校准集偏差 |

### 5.3 概念卡与白砚译注

- 每关一张五栏概念卡；"试一试"会一键打开 Forge 并载入对应场景。现实栏写具体年代与系统，例如：Rosenblatt 感知机 1958、Minsky–Papert 1969、反向传播 1986、Q 学习 1989、LeNet 1989、LSTM 1997、word2vec 2013、Adam 2014、ResNet 2015、蒸馏 2015、BPE 2016、AlexNet 2012、Transformer 2017、RLHF 2017/2022。
- 每章开头是白砚的一页译注，共 16 页。他用身边的词描述从没见过的东西，每页有一句像疯话的句子，玩家通关这一章后才看懂它说得很准。页上还有一段从回响石上描下的脉纹，一条失败的曲线，或一句"它今天又背答案了"。

| 章 | 疯话 | 通关后看懂的 |
|---|---|---|
| 1 | "它在每一个分叉处等。" | 神经元在阈值处二选一；网络是一层层分叉 |
| 2 | "同一件事，我用两把尺子量，它只信大的那把。" | 特征尺度：数值大的特征压过数值小的 |
| 3 | "我给每种错误标了价，价钱决定它先改哪一个。" | 损失函数：给错误定价 |
| 4 | "它每次只摸脚下的坡，却走到了最低的那间屋。" | 梯度下降：只用局部坡度找到谷底 |
| 5 | "错误从尽头一站一站递回来，每一站只认自己的那一份。" | 反向传播：链式法则 |
| 6 | "它把每一页都背下来了，所以它从没读过书。" | 过拟合：训练集满分不等于学会 |
| 7 | "考卷发下去之前，答案已经在我口袋里了。" | 数据泄漏：测试集被偷看过 |
| 8 | "我只有一枚小印章，却把整张纸都盖满了。" | 卷积核共享权重 |
| 9 | "它答对了，可它盯着的不是我指的那里。" | 捷径特征 |
| 10 | "意思相近的字，住在同一条街上。" | 嵌入：用法相近的字挨在一起 |
| 11 | "每个字都先举手问全句：谁跟我有关？" | 注意力 |
| 12 | "它说话像抽签：每个字都是从袋子里摸出来的。" | 自回归生成 |
| 13 | "它不在乎我要什么，只在乎我给它记了几分。" | 奖励 ≠ 本意 |
| 14 | "它学会的不是答案，是我点头的样子。" | 偏好学习会学到讨好 |
| 15 | "去年的风教它的话，今年的风不认。" | 分布漂移 |
| 16 | "我把一本厚书缩成一页纸，书里的人还认得出自己。" | 蒸馏与量化 |

## 6. 温室 Hub

- 2.5D 手绘纵剖面：深井的中层，即温室。窗外是井口镇（风塔、驼队营地、学校的屋顶）；脚下的观察窗里是回响石，脉纹每完成一章就多亮一段。
- 中央是培养机，"它"的光核悬在里面：第 1 章是一枚光点，之后随章节长出枝节（第 5 章长出第二层，第 8 章长出"眼"，第 11 章长出"口"）；它的形态由玩家主线模型的结构决定，因此每个玩家的"它"长得不一样。
- 四周的苗床上是玩家存下的模型（§4）。委托模型种在靠窗那一排，共 16 个，会连到镇上那个地点，实时跑着：出发预报、整理后的旧日志、水量预估、省电的沙日训练、沙暴号、三十位病人的回访建议、回访名单、盖章检测、分拣器、谜语接龙、童谣、问询台、驼队调度员、审查题库、冬季换装和全镇一周。
- 回响：每完成一章（16 次），井底的回响石亮起一段脉纹，一声低鸣顺着井道传上去，风塔光束扫过镇子，点亮委托人所在的地点（圣经 §5.1）。回响石不给答案，只在委托真的替镇民做成事时回响。
- 点"它"打开档案、手册、设置；"它"开口时用玩家的模型说话（§2.4）。
- 叙事预算：每章开头最多 3 行对白 + 一页译注，每关简报 ≤ 3 行，整作叙事 ≤ 40 分钟（圣经 §2.4）；16 章靠"每章一个委托、一页译注、一句疯话、一个伙伴变化"撑起，不加支线。

## 7. 美术与音频

**美术方向"温室与辉光"：** 叙事层是夜里的暖光玻璃房，玻璃上落着细沙，暖灯照着培养机，光核在中央呼吸。工作层用 `oo_kit` 玻璃面板：神经青 `#4DE3FF` 表示正值、激活和数据流，品红 `#FF4D9D` 表示负值、误差和梯度；用颜色、线型、符号三重编码，保证色盲可读。决策场和注意力矩阵是本作的招牌画面，训练过程本身就可以做成商店页动图。

**动效原则：** 光点流动、植物生长、边界移动都来自真实的训练状态，美术只加不改变状态的修饰（辉光、粒子）。

**音频：** 井道里的风沙声、培养机的低频嗡鸣、远处的沙暴号。**训练声化**见 §3。每章一首分层曲：第 1 章只有单音正弦，每章加一个声部；第 11 章"它"开口时加入人声采样；结局按抉择分两种配器。

## 8. 技术

v0.1 的代码要做结构性重构，重点在于删掉经济、把文案和判定移进核心层、接入共享层：

| 项 | v0.1 现状 | v3 |
|---|---|---|
| 关卡数据 | `content.rs` 只有 id、标题、机制；文案、答案、提示散在 `ooi_app/src/i18n.rs`（1958 行）的 `match` 里 | `ooi_core::content::<chapter>.rs` 一关一个常量，字段按圣经 §6.1；文案用 `Tr { en, zh }` 放在同一常量里 |
| 机制 | 16 种 `PuzzleKind`，其中 `Pick` / `Step` 用于选择题判定 | `Pick` 只用于预测；`Step` 删除；新增机制与每章 Forge 零件见 [syllabus.md](syllabus.md) 各章开头；逐关操作与判分见 [levels.md](levels.md) |
| 应用 | `level.rs` 4647 行，每种机制的视图、输入、判定混在一起 | `ooi_app/src/mech/<kind>.rs` 每种机制一个模块，只管绘制与输入；判定全部在 `ooi_core::puzzle` |
| 经济 | `economy.rs`、升级屏、离线收益 | 删除；存档迁移时丢弃相关字段 |
| 进度 | `progression.rs` 线性解锁，`achievements.rs` | 按 `requires` DAG 解锁（每章 8 关，章内按关卡顺序，章间按先修表）；成就保留，改用新的关卡 id 与星级 |
| Forge | `lab.rs`：MLP + XOR / Ring / Spiral（已真实训练） | `ooi_core::forge::{module, data, train, table, regress, optim, eval, conv, seq, attn, sample, calib, rl, pref, deploy}`，模块是可组合的层 |
| 共享层 | 自有 theme / toast / ui / save_io | 换成 `oo_kit`（theme、ui、toast、save、audio、时间轴、指证、概念卡、译注、井与镇 hub、直方图、分享码、诊断面板）；ooi 的辉光与玻璃材质贡献回 `oo_kit` |
| 调试变量 | `OOI_START_LEVEL` 等 | `OOI_FRESH / LANG / SCREEN / TASK / REF / RUN / SCREENSHOT` |

- **内容规模：** 128 关，每关一个常量，每章一个文件（`content/c01.rs` … `c16.rs`，每个 8 关）。每章 8 关，固定位置：第 1–3、5–6 关为谜，第 4、7 关为障，第 8 关为托；共 80 谜 / 32 障 / 16 托。每关 10–25 分钟，主线 40–50 h，全收集 90 h+；手册 90–140 页；一次发布。
- **id：** 原有 48 个 id 原样保留为遗留 id（其中的 `chN_` 是旧章号，不等于现在的章号，代码按 `chapter` 字段读章，不按前缀推）；新增 80 个写成 kebab-case `cNN-slug`（圣经 §6.1）。这 48 个 id 落在第 1、4–16 章，第 2、3 章没有。
- 存档迁移：v0.1 的 37 个 id 与随后重编的 id，保留的照搬完成记录；星级统一重置为 ★1 并标记"新规则可再挑战"。如果玩家已通关旧版某章，对应的新关开放为可直接进入。
- 与算力起源共用权重格式：第 15–16 章跑在起源机（ooc 的第六台复刻机）上（剧情内），16-8 finale 用的是与 ooc 8-6 相同的模型格式与周期预算；玩家的模型也可以导出，在 ooc 的自由机台里运行。读取 ooc 存档只用于替换台词（圣经 §2.5）。
- CI：每关参考解在测试集上 ★3；故障关的初始方案必败，且证据区间非空；预测答案由训练计算；`alt_refs` 张力；DAG 无环；文案完整；字符表校验；v0.1 存档样本可迁移；Forge checksum 三平台一致；大纲校验（128 行、每章位置与类型、80 / 32 / 16、新 id 为 kebab-case、48 个旧 id 各一次）。
